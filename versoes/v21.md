# v21 — Correções de segurança, dados e lógica

## Contexto

O arquivo chegou com ~2.600 linhas num HTML só. A revisão encontrou
problemas concretos, que foram corrigidos aqui.

## Bugs de precificação ( mexem em dinheiro)

### 1. Hotel: "Pessoas" nunca zerava o custo

```js
// ANTES
const totalHotel = hotelDias * hotelPess * (hotelV / (hotelPess || 1));
// DEPOIS
const totalHotel = hotelPess > 0 ? hotelDias * hotelV : 0;
```

O campo "Pessoas" agora realmente controla: 0 = sem hospedagem.

### 2. Carro: rótulo dizia "Km x2", a conta fazia `* 1`

Mantive a fórmula original e corrigi o rótulo para "Km total".
Detalhamento em [v19.md](v19.md).

## Bug de lógica (perda de informação)

### Etapa "concluída" grudava na posição

O "concluído" era salvo por **índice** da lista. Se você reordenasse
ou apagasse uma etapa, a marcação migrava para a etapa errada.

Agora cada etapa tem um `id` próprio (`novoIdEtapa()`, com contador
contra colisão) e a marcação segue a etapa.

## Segurança

- `status` e `id` vindos do `.json` importado passam por validação
  (`normalizarProjeto`) — um arquivo adulterado não injeta nada
- `textContent` no lugar de `innerText` onde entra dado do usuário
- `localStorage` com `try/catch`: se a cota estourar, o sistema avisa
  em vez de perder a gravação em silêncio

## Robustez

- Trava contra duplo clique em "Salvar" (não grava duas vezes)
- Debounce de 150 ms no `calcular()` (antes re-renderizava a tabela
  inteira a cada tecla digitada)
- `Esc` fecha os dois modais
- `role="dialog"` + `aria-modal` nos modais
- Foco visível (o `outline: none` global sumia com o foco do teclado)
