# v26 - Bug critico: abas 2, 3 e 4 abriam em branco

**Severidade: alta.** O sistema era inutilizavel nas tres abas.

## O sintoma

Clicar em "Lista Materiais", "Equipe de Campo" ou "Painel Financeiro"
abria a pagina com o cabecalho e o menu, mas o corpo ficava **em
branco**. A Aba 1 funcionava normalmente.

## A causa

O arquivo original era um HTML unico com 4 abas. Para esconder as
abas que nao estavam ativas, cada `<section>` nascia com `class="hidden"`:

```html
<section id="tab-materiais" class="tab-section hidden flex-col gap-4">
```

Quem tirava o `hidden` era a funcao `switchTab()`, chamada pelos botoes
`onclick="switchTab('materiais')"`.

Quando cada aba virou um **HTML proprio**, esse `hidden` nao tinha mais
quem o tirasse: o menu virou `<a href="materiais.html">` (navegacao de
verdade), nao um botao que chamava JavaScript.

O script que sobrou no rodape de cada pagina fazia apenas isto:

```js
document.querySelectorAll('.menu-btn').forEach(function (b) {
  if (b.getAttribute('href') === ativo) b.classList.add('ativo');
});
```

Marca o botao do menu como ativo. **Nao mexe no `hidden` do conteudo.**

Resultado: `.tab-section` ficava com `display: none` e a pagina abria
vazia.

## A correcao

O script de rodape agora tambem revela o conteudo:

```js
function revelar() {
document.querySelectorAll('.menu-btn').forEach(function (b) {
  if (b.getAttribute('href') === ativo) b.classList.add('ativo');
  });

  // Tira o "hidden" da secao desta aba.
  var sec = document.getElementById('tab-' + ativo.replace('.html', ''));
  if (sec) {
  sec.classList.remove('hidden');
  sec.classList.add('flex');
  }
}

if (document.readyState === 'loading') {
document.addEventListener('DOMContentLoaded', revelar);
} else {
  revelar();
}
```

O `if (document.readyState === 'loading')` cobre os dois casos: script
no `<head>` (ainda carregando) ou ja no fim do `body` (pronto).

## Por que o teste nao pegou isso

Os testes antigos conferiam **numeros** (total de materiais, quantidade de
itens), nao **visibilidade**. O JavaScript estava perfeito: a tabela tinha
as 19 linhas e o total batia R$ 14.790,85. O que falhava era o CSS
aplicado ao container.

Diagnostico: rodei uma pagina real e li `getComputedStyle(section).display`,
que devolvia `none` com 19 linhas no DOM. Isso distingue "o JS nao
rodou" de "o JS rodou mas o elemento esta escondido".

## Validacao apos a correcao

| Pagina | display | altura visivel | itens |
|---|---|---|---|
| 1. Proposta | flex | 1719 px | - |
| 2. Materiais | flex | 994 px | 19 linhas |
| 3. Equipe | flex | 338 px | 3 tecnicos |
| 4. Financeiro | flex | 418 px | 59 elementos |

Todas as quatro abas com conteudo visivel.

## Licao

Teste de interface precisa verificar **o que o usuario ve**, nao so o
que existe no DOM. Um elemento pode estar la, com os dados corretos, e
mesmo assim invisivel.
