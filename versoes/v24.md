# v24 — Preparação para servidor real

## Objetivo

O sistema vai rodar num servidor **sem Node**. Tudo passa a ser
HTML, CSS e JavaScript estático, com pastas `.json` e `.xlsx` no
servidor, e publicação no GitHub.

## O que mudou

### 1. Aviso correto para HTTP sem HTTPS

`showDirectoryPicker()` é uma API de **contexto seguro**. Testei o
comportamento real:

| Onde | `isSecureContext` | `showDirectoryPicker` |
|---|---|---|
| `file://` (dois cliques) | `true` | disponível |
| `http://localhost` | `true` | disponível |
| `http://servidor.com` | **`false`** | **não existe** |

Antes, o sistema dizia "use Chrome ou Edge", o que era **incompleto**:
num servidor HTTP sem HTTPS o problema não é o navegador. Agora o
aviso distingue os dois casos e dá as duas saídas (HTTPS, ou "Salvar
no PC").

### 2. Nenhuma outra dependência de ambiente

Conferi todo o código:

- **Nenhum `fetch()`** — os dados vêm de `<script src>`
- **Nenhum caminho `file:///`** hardcoded
- **Nenhuma referência a `localhost`**
- Todos os caminhos são **relativos** (`../css/`, `../js/`, `../data/`)

Ou seja: o mesmo código funciona em `file://`, em `http://` e em
`https://`, sem configuração.

### 3. Documentação

- `README.md` — visão geral, instalação, riscos
- `versoes/` — histórico versionado (esta pasta)
- `instrucoes/` — guias de uso e de instalação no servidor

## O que NÃO mudou

- Nenhuma regra de cálculo
- Nenhum arquivo de layout
- Nenhum teste foi quebrado

Por isso **não rodei a suíte completa** — nenhuma das regras que os
testes verificam foi tocada. Rodei apenas o que mudou: `node --check`
nos 8 arquivos JS e uma verificação real no navegador.

## Se um dia houver servidor de verdade

Toda a gravação está isolada em **uma função**: `gravarNaPasta()` em
`js/06-arquivos.js`. Com servidor, troque essa função por um `fetch()`
POST e o resto continua igual — nomes, data, cliente, botões, avisos.

A permissão de pasta, que hoje é o ponto fraco do navegador, vira
permissão de servidor, que é bem mais fácil.
