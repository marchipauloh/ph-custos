# v22 — Separação em pastas

## O que mudou

O arquivo único de 155 KB foi quebrado em pastas:

```
html/    4 páginas (uma por aba)
css/     PH_custos.css
js/      7 arquivos
data/    valores.json + valores.js
```

## O problema que a separação criou

Materiais e equipe viviam **na memória do JavaScript**. Trocar de aba
não destruía nada; trocar de **página** destrói. Clicar em "Equipe"
sumiria com os 19 materiais.

Resolvido com um **rascunho no localStorage**, lido no início de cada
página. O rascunho não é o trabalho: ele só impede que o texto se
perca ao navegar. O que importa (vai para Financeiro, PDF e Excel)
só existe depois de "Salvar".

4 bugs sem erro visível no console, encontrados pelos testes:

|---|---|
| `carregarEmpresa()` quebrava em Materiais/Equipe | tabela vazia |

O último era o mais grave: a gravação era engolida por um erro.

## Detalhe importante: JSON vs YAML

Escolhi **JSON**, e não YAML, porque o `.json` é nativo do navegador
(`JSON.parse`) — sem biblioteca. YAML exigiria uma lib para ler no
cliente.

O `.json` é o arquivo editado à mão. O `data/valores.js` é o gerado,
que é o que o sistema carrega. Motivo: **o navegador bloqueia
`fetch()` de arquivo local** (CORS). Se usasse o `.json` direto, só
funcionaria com servidor.

O `ferramentas/gerar-config.js` converte e **valida antes de
escrever** (material sem preço, parcelas que não somam 100% → avisa
e não gera).

## Recomendações que ficaram de fora (de propósito)

Extrair o domínio para funções puras, `EditorParcelas` para eliminar
duplicação e migrations versionadas foram sugeridos, mas **não
implementados**: para um app de arquivos estáticos, o ganho não paga
o risco de mexer em algo que funciona.

## Um incidente que mudou o processo

Uma edição por regex destruiu 340 linhas do `03-telas.js`. O gerador
não avisou — gerou as 4 páginas como se estivesse tudo certo. Dois
aprendizados ficaram no código:

- O gerador **não usa mais números de linha fixos**; acha cada seção
  pelo marcador do HTML
- O gerador agora **falha alto**: se um `<script>` cair dentro de um
  comentário, avisa em vez de gerar página quebrada
