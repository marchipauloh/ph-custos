# v25 - Tailwind compilado (sem CDN)

## O que mudou

O aviso `cdn.tailwindcss.com should not be used in production` foi
eliminado. O CSS agora e gerado no build e servido localmente.

## Antes / depois

```html
<!-- ANTES -->
<script src="https://cdn.tailwindcss.com"></script>

<!-- DEPOIS -->
<link rel="stylesheet" href="../css/PH_custos_compilado.css">
```

## Por que o CDN era um problema

O `cdn.tailwindcss.com` **gera o CSS em tempo de execucao no
navegador**. Isso significa:

- ~110 KB de CSS processado a cada visita
- Se a internet cair, o layout inteiro quebra
- O proprio Tailwind avisa que nao e para producao

## Como gerar o CSS

```bash
npm install            # so na primeira vez
npm run css            # gera public/css/PH_custos_compilado.css
npm run css:watch      # regenera sozinho ao salvar
```

O gerador le `build/entrada.css`, que aponta para:

| Fonte | Por que |
|---|---|
| `public/index.html` | classes da tela de entrada |
| `public/html/*.html` | classes das 4 abas |
| `public/js/*.js` | **importante**: varias classes so existem dentro de template literals (ex.: `bg-orange-950/40`) |
| `public/css/PH_custos.css` | utilitarios proprios |

## Impacto no tamanho

| | Antes | Depois |
|---|---|---|
| CSS por visita | ~110 KB gerado em runtime | 28,9 KB estatico |
| Dependencia de internet | sim (Tailwind + FontAwesome) | so FontAwesome (icones) |

## O que NAO mudou

O visual e identico. Comparei o DOM renderizado antes e depois, com o
CSS injetado removido: **290 linhas iguais, 1 linha diferente** (a propria
tag do link).

Verificado no navegador:
- 3 stylesheets carregados
- `nav` com `display: grid`
- logo 46x46 px
- cores aplicadas (`h1` branco, body `#0f1117`)

## Cuidado ao mexer

Se voce adicionar uma classe nova **dentro de uma string do JS**, rode
`npm run css` de novo. Sem isso, a classe fica sem estilo.

Exemplo de classe que vive no JS:

```js
`<td class="bg-orange-950/40 py-2 text-right">`
```

O `build/entrada.css` ja aponta para `public/js/*.js` justamente para
cobrir esse caso.

## Bug encontrado no caminho

O `package.json` foi gravado com BOM (Byte Order Mark) e o Node
rejeitou:

```
SyntaxError: Unexpected token '\uFEFF'
```

Se ao rodar `npm run css` aparecer algo assim, o arquivo foi salvo com
BOM. O jeito e salvar sem BOM:

```js
fs.writeFileSync('package.json', JSON.stringify(p, null, 2) + '\n', 'utf8')
```
